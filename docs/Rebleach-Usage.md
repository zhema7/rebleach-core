# Rebleach Usage Guide

English | [简体中文](Rebleach-使用说明.md)

Version: v0.5 (T1–T4 + server enrollment)
Supported OS: Windows 10 / 11 x64
Companion document: *Rebleach Installation Guide* (installation, tray, PIN, and other basics follow that document)

---

## 1. What this guide covers

After deployment, Rebleach can be used in three ways:

| Usage | Typical scenarios | Entry point |
|---|---|---|
| GUI takeover | Hands-on remote operation, viewing the screen, transferring files | Rebleach Controller window |
| CLI automation | Batch command execution, port forwarding, SSH access, Ansible | `rebleach-client.exe` / `rebleach-proxy.exe` |
| Server enrollment | Bulk agent deployment, centralized authorization | Admin pages under `/admin` |

The GUI and CLI can be used at the same time without interfering with each other. The CLI does not open a screen
channel, and the agent does not start screen capture.

---

## 2. GUI: up and running in five minutes

### 2.1 Prepare the controlled device

1. Make sure the tray icon is present. Right-click it to see "Copy ID" and "Copy PIN".
2. Send the ID to the operator; share the PIN separately (verbally or through another channel).
3. If Windows Firewall prompts on first run, allow access on **private networks** (this only affects LAN direct
   connections; relayed connections are unaffected).

### 2.2 Connect from the controller

1. Open Rebleach Controller.
2. Enter the controlled device ID under "Remote connection" and click "Connect".
3. Enter the PIN when prompted.
4. Once connected, the screen appears. The top toolbar provides:
   - Keyboard/mouse control toggle
   - Multi-monitor switching
   - File transfer (bidirectional drag-and-drop, resumable)
   - Voice chat / text messages
   - Terminal tabs (equivalent to a local command line)

### 2.3 LAN direct connection (optional)

On the same LAN, latency is lower: enter the controlled device's private IP plus the 6-digit passcode, or click
"Search devices" to discover it automatically.

### 2.4 The "Access & SSH" card

The "Access & SSH" card on the controller's settings page connects the client to a self-hosted server:

1. Enter the server address (for example `wss://signal.example.com/ws`). Click "Save credentials" to store the admin
   username and password as well.
2. Enter the controller device ID, click "Generate public key", then "Register public key" to upload it to the server.
3. Click "Generate SSH config" to rebuild `~/.ssh/config.d/rebleach.conf` from the server's current grants.
4. To add an agent, choose a validity period (15 minutes / 1 hour / 24 hours), generate an enrollment token, and copy
   the one-click install command.

> The admin username and password are stored in plain text in `%APPDATA%\rebleach-controller\config.json`. Only use this
> on a personal device you control.

## 3. CLI: common conventions

### 3.1 Executables

The installation directory contains two programs:

| Program | Purpose |
|---|---|
| `rebleach-client.exe` | Main program: GUI plus all subcommands |
| `rebleach-proxy.exe` | Protocol bridge called by `ssh` through ProxyCommand |

Add the installation directory to `PATH`; otherwise the ProxyCommand generated by `ssh-config` will not find
`rebleach-proxy`.

### 3.2 Global options

The following options go before the subcommand:

| Option | Default | Description |
|---|---|---|
| `--server <url>` | `ws://127.0.0.1:8088/ws` | Signaling server address; specify explicitly in production |
| `--key-file <path>` | `%APPDATA%\rebleach\identity.json` | Device identity key (used for TOFU) |
| `--auth <code>` | none | LAN direct-connection passcode |
| `--stun <url>` | built-in default | Repeatable or comma-separated |
| `--turn <url>` | built-in default | Format: `turn:user:pass@host:port` |

Example:

```powershell
rebleach-client --server wss://signal.example.com/ws exec dev-0001 -- "hostname"
```

### 3.3 Exit codes

| Command | Exit code meaning |
|---|---|
| `exec` | **The remote command's actual exit code** (0 on success, non-zero passed through) |
| `tunnel` / `proxy` | 1 when the link fails or the event stream ends |
| `ssh-config` / `inventory` / `keygen` / `setup` / `term-replay` | 0 on local success; non-zero on argument, network, or I/O errors |

## 4. Server deployment and access configuration

### 4.1 Start the server

```bash
rebleach-server \
  --addr 0.0.0.0:8088 \
  --db ./rebleach.db \
  --admin-user admin --admin-pass <admin-password> \
  --packages-dir ./packages \
  --public-url https://signal.example.com \
  --turn-url turn:signal.example.com:3478 \
  --turn-secret <coturn-static-auth-secret>
```

| Option | Default | Description |
|---|---|---|
| `--addr` | `0.0.0.0:8088` | Listen address |
| `--db` | `./rebleach.db` | SQLite database; schema is created on first start |
| `--admin-user` / `--admin-pass` | `admin` / `admin` | Admin Basic Auth credentials; **change them before going live** |
| `--packages-dir` | `./packages` | Package center directory, also used for one-click agent distribution |
| `--public-url` | empty | Public address used to build one-click install commands; inferred from request headers when empty |
| `--turn-url` / `--turn-secret` | empty | coturn URL and `static-auth-secret`; no TURN credentials are issued when empty |
| `--turn-ttl` | `600` | Lifetime of ephemeral TURN credentials (seconds) |

When running behind a reverse proxy, set `--public-url` explicitly; otherwise the one-click install command may end up
containing an internal address.

### 4.2 Admin pages

Open `http://<host>:8088/admin`. The browser prompts for Basic Auth using `--admin-user` / `--admin-pass`.

| Page | Purpose |
|---|---|
| `/admin/devices` | Device list and online status |
| `/admin/grants` | Grants between controllers and agents |
| `/admin/packages` | Package center: upload / download installers |
| `/admin/audit` | Audit log |
| `/admin/access` | Access configuration: enrollment tokens, controller public keys |

### 4.3 Grants and public keys

1. On `/admin/devices`, confirm that both the controller and the agent have registered.
2. On `/admin/grants`, create an active "controller → agent" grant.
3. On `/admin/access`, register the controller's public key (the client's `setup` command can do this automatically).
4. The agent fetches the public keys for active grants every 60 seconds and writes them to the local
   `ssh_authorized_keys`.

To revoke access, delete the corresponding grant or public key; the agent removes it within one minute.

## 5. One-click agent installation

### 5.1 Generate an enrollment token

On `/admin/access`, choose a validity period (15 minutes / 1 hour / 24 hours) and generate a token:

- The token is single-use and becomes invalid immediately after a successful install.
- Unused tokens can be deleted at any time; deleting a used token returns 404.
- If a token leaks, revoke it and generate a new one.

### 5.2 Run the installer

On the target machine, open PowerShell **as administrator**:

```powershell
irm "<server>/bootstrap/install.ps1?token=<token>" | iex
```

The script will:

1. Call `POST /bootstrap/claim` to exchange the token for a device ID;
2. Download the agent installer from `/bootstrap/agent`;
3. Install silently, register the Windows service, and come online automatically.

> Place an `.exe` installer whose filename contains both `rebleach` and `agent` in `--packages-dir`; otherwise
> `/bootstrap/agent` returns 404.

### 5.3 Verify

After installation, return to `/admin/devices`; the new device and its online status should appear. If it does not:

- Check that the target machine can reach the address behind `--public-url`.
- Check whether the enrollment token has expired or was already used.
- Check whether the `RebleachAgent` service is running.

## 6. exec: run one-off remote commands

### 6.1 Basic usage

```powershell
rebleach-client exec <device-id> -- "<command>"
```

Examples:

```powershell
# System information
rebleach-client exec dev-0001 -- "systeminfo"

# PowerShell
rebleach-client exec dev-0001 -- "powershell -NoProfile -Command Get-Process | Sort-Object CPU -Descending | Select-Object -First 10"

# With a timeout in seconds; exits with an error when it expires
rebleach-client exec dev-0001 --timeout 60 -- "ping -n 10 127.0.0.1"

# JSON output for scripts
rebleach-client exec dev-0001 --json -- "whoami"
```

### 6.2 Behavior

- Executes in **pipe mode** without creating a window, so no console window flashes on the agent.
- `stdout` and `stderr` are merged into a single output stream.
- The command is prefixed with a UTF-8 code page switch (`chcp 65001`). Output is plain text with **no ANSI escape
  sequences**.
- Background processes (for example `start /b`) are not waited for; `exec` waits only for the command itself.
- **Without `--timeout`, it waits indefinitely.** Set a timeout explicitly in automation scripts.
- `--json` output fields: `exit_code`, `output`, `duration_ms`.

### 6.3 Checking results in scripts

```powershell
rebleach-client exec dev-0001 --timeout 30 -- "sc query RebleachAgent"
if ($LASTEXITCODE -ne 0) {
    Write-Host "Service failure, exit code $LASTEXITCODE"
}
```

## 7. tunnel: port forwarding

### 7.1 Basic usage

```powershell
rebleach-client tunnel <device-id> --local <local-port>:<target>
```

The target can be written in two ways:

| Form | Meaning |
|---|---|
| `127.0.0.1:3306` | Port on the agent itself |
| `10.0.0.8:80` | Another machine on the agent's private network (**must be an IP**) |
| `ssh` | The agent's built-in SSH server (recommended) |

Examples:

```powershell
# Map the agent's MySQL to local port 13306
rebleach-client tunnel dev-0001 --local 13306:127.0.0.1:3306

# Multiple rules at once
rebleach-client tunnel dev-0001 `
  --local 13306:127.0.0.1:3306 `
  --local 18080:10.0.0.8:80 `
  --local 2222:ssh
```

Then connect to the local port:

```powershell
mysql -h 127.0.0.1 -P 13306 -u root -p
ssh -p 2222 Administrator@127.0.0.1
```

### 7.2 Behavior

- The local listener is always bound to **127.0.0.1**, so only the local machine can access it; it is never exposed to
  the LAN.
- Each rule gets its own channel and supports multiple connections (each with its own `cid`).
- **Destination restrictions**: only loopback and private IPs are allowed (10/8, 172.16/12, 192.168/16, 127/8,
  169.254/16, IPv6 private ranges). Domains and public IPs are rejected to prevent the agent from being used as a
  public jump host.
- To forward to a domain, resolve it to an IP on the agent first.
- Press `Ctrl+C` to stop; all local listeners close with it.

## 8. SSH access

### 8.1 How it works

`rebleach-proxy` treats the stdin/stdout of the local `ssh` process as a TCP connection and carries it over the tunnel
channel to the agent:

```
ssh → ProxyCommand(rebleach-proxy) → signaling → tunnel → agent
                                                           ├─ rblssh: built-in SSH server
                                                           └─ 127.0.0.1:22: local sshd
```

The agent needs no public IP and no open port 22. Authorization is managed centrally by the server; controllers no
longer copy public keys to each machine.

### 8.2 One-step setup (recommended)

```powershell
rebleach-client --server wss://signal.example.com/ws setup `
  --device <controller-id> --user admin --pass <admin-password>
```

`setup` performs the following in order:

1. Generates (or reuses) an operator key at `%APPDATA%\rebleach\ssh\<controller-id>.key` and tightens the ACL on Windows;
2. Registers the public key through `POST /api/v1/ssh-keys`;
3. Reads active grants from `GET /api/v1/grants` and renders `~/.ssh/config.d/rebleach.conf`;
4. Checks whether `~/.ssh/config` contains `Include ~/.ssh/config.d/*.conf` and warns if it does not.

To avoid leaving the password in shell history, use an environment variable:

```powershell
$env:RBLEACH_PASS = "<admin-password>"
rebleach-client --server wss://signal.example.com/ws setup --device <controller-id>
```

Add `--print` to preview the config without writing it; use `--out <path>` to choose another output location.

### 8.3 Manual key generation and registration

```powershell
# 1. Generate a key (or copy the public key from the "Access & SSH" card)
rebleach-client keygen --device dev-0001

# 2. Paste the printed public key into /admin/access (or call POST /api/v1/ssh-keys)
```

- The private key is written to `%APPDATA%\rebleach\ssh\dev-0001.key` by default.
- One public key per line, associated with the controller's device ID.
- If this machine is also the agent, `keygen --device dev-0001 --add` writes the key to the local authorized-keys file
  directly.

> The built-in SSH server accepts public-key authentication only; password login is not supported.

### 8.4 Authorized-key sync

The agent fetches authorized keys from `GET /agent/ssh-keys` every 60 seconds:

| Runtime form | Path |
|---|---|
| Installed agent (Windows service) | `%ProgramData%\Rebleach\ssh_authorized_keys` |
| Standalone CLI / manual run | `%APPDATA%\rebleach\ssh_authorized_keys` |

New grants take effect within one minute without restarting the service; revocations are also removed within one
minute.

### 8.5 Generate the ssh config

```powershell
rebleach-client ssh-config --controller <controller-id>
```

- `--controller` adds `--id` to the ProxyCommand so authorization checks use the controller identity.
- By default, devices are collected from the server's active grants; you can also pass `--device dev-0001 --device dev-0002`
  explicitly.
- The generated content looks like:

```
Host rbl-dev-0001
    HostName rblssh
    Port 22
    User Administrator
    ProxyCommand "rebleach-proxy" --server wss://signal.example.com/ws --id <controller-id> --device dev-0001 rblssh
    StrictHostKeyChecking accept-new
```

Then simply run:

```powershell
ssh rbl-dev-0001
```

If the agent already runs a standard sshd, switch to the local sshd backend:

```powershell
rebleach-client ssh-config --controller <controller-id> --backend sshd
```

## 9. inventory: generate an Ansible inventory

```powershell
$env:RBLEACH_PASS = "<admin-password>"
rebleach-client inventory --user admin --only-online
```

- Fetches devices from the signaling server via `GET /api/v1/devices` and includes only online devices with the
  `controlled` role.
- Writes `%APPDATA%\rebleach\inventory.ini` by default, with one ProxyCommand per host.
- `--print` prints without writing a file; `--pass` also works but is discouraged because it stays in command history.

Then run:

```powershell
ansible -i $env:APPDATA\rebleach\inventory.ini rebleach -m ping
ansible -i $env:APPDATA\rebleach\inventory.ini rebleach -m win_command -a "whoami"
```

Requirement: `ssh` on the control machine must be able to reach the agent through `rebleach-proxy` (see section 8), and
the corresponding public key must be authorized.

## 10. proxy: standalone use

`rebleach-proxy` is a pure protocol bridge. It only does three things: connect to signaling, open a tunnel, and connect
stdin/stdout to the remote byte stream.

```powershell
rebleach-proxy --server wss://signal.example.com/ws --device dev-0001 --stdio rblssh
```

| Option | Description |
|---|---|
| `--server` | Signaling address |
| `--device` | Target agent ID |
| `--id` | This machine's device ID on signaling (use the controller ID) |
| `--auth` | LAN direct-connection passcode (optional) |
| `<target>` | Positional argument, default `rblssh`; `127.0.0.1:22` also works |

Note: **stdout carries protocol data only**; all logs go to stderr, so it can be safely invoked by `ssh`, `nc`,
database clients, and similar programs.

## 11. Terminal recording and replay

### 11.1 Automatic recording

Terminal interaction through the controller is recorded by default under:

```
%APPDATA%\rebleach\recordings\<session-id>\term-<tab>.cast
```

The format is asciicast v2 (JSONL), and the header contains context:

```json
{"version":2,"width":120,"height":30,"vars":{"rebleach_session":"...","rebleach_device":"dev-0001","rebleach_sid":"1"}}
```

Each subsequent line is an event: `[seconds, "o", output-text]`.

To disable recording (set before starting the controller):

```powershell
$env:RBLEACH_TERM_RECORD = "0"
```

### 11.2 Replay

```powershell
# Plain-text replay (useful for searching and auditing)
rebleach-client term-replay "$env:APPDATA\rebleach\recordings\sess-xxxx\term-1.cast"

# Timeline replay
asciinema play "$env:APPDATA\rebleach\recordings\sess-xxxx\term-1.cast"
```

## 12. Network and security

### 12.1 Connection paths

1. **P2P direct connection** is preferred (lowest latency, no relay usage).
2. If hole punching fails, Rebleach automatically falls back to **TURN relay**, transparently to the user.
3. The relay only forwards encrypted byte streams; the server never holds device private keys.

### 12.2 Ports

| Port | Direction | Purpose |
|---|---|---|
| TCP 7681 | Agent listener | LAN direct-mode signaling |
| UDP 7682 | Agent listener | LAN device discovery |
| TCP 8088 | Server | Signaling WebSocket, admin pages, access APIs |
| UDP 3478 / TCP 3478 | Server | TURN |
| UDP 49160–49360 | Server | TURN relay port range |

For cross-network use, only the server's signaling and TURN ports must be reachable; the agent needs no inbound ports.

### 12.3 Credentials and tokens

- **Admin Basic Auth**: defaults to `admin/admin`; change it before going live, and expose `/admin` only on an intranet
  or through a VPN.
- **Enrollment tokens**: single-use and expiring, used only to obtain a device identity; delete and regenerate them if
  leaked.
- **TURN credentials**: short-lived (600 seconds by default), issued on demand by the server; clients never store
  long-term secrets.

### 12.4 TOFU trust

On first connection, the peer's public key is pinned in `%APPDATA%\rebleach\known_peers.json`. If the peer's key changes
later, the connection is rejected (`pubkey_mismatch`).

- After a legitimate OS reinstall or device replacement, delete the corresponding entry and reconnect.
- **Do not delete this file casually**; it prevents man-in-the-middle device impersonation.

## 13. FAQ

| Symptom | Troubleshooting |
|---|---|
| Connection stays at "waiting for peer" | Is the agent online (tray icon / `RebleachAgent` in `services.msc`)? Does `--server` point to the right server? |
| `pubkey_mismatch` | The peer was reinstalled or changed its identity key. After confirming, delete the corresponding entry in `known_peers.json` |
| Admin pages / APIs return 401 | Wrong Basic Auth credentials; make sure they match `--admin-user` / `--admin-pass` |
| One-click install says the token is invalid | The token expired or was already used (single-use); generate a new one on `/admin/access` |
| One-click install returns 404 | `--packages-dir` has no `.exe` whose filename contains both `rebleach` and `agent` |
| `ssh` still says Permission denied after registering a key | The agent may need up to 60 seconds to sync; verify the grant is active and the key is associated with the correct controller ID |
| Garbled Chinese output from `exec` | The command is prefixed with UTF-8; if the target program forces GBK, transcode in the command itself, for example by setting `[Console]::OutputEncoding` in PowerShell |
| `tunnel` says "target must be host:port or ssh" | Check the `--local` format, for example `13306:127.0.0.1:3306` |
| `tunnel` rejects the target | Only loopback/private IPs are allowed; resolve domains and public IPs to a private IP first |
| `ssh` cannot find `ProxyCommand` | Add the Rebleach installation directory to `PATH`, or use `--proxy-bin` with a full path |
| `inventory` returns an empty list | Devices must be online; make sure `--user/--pass` match the server's admin account |
| Relay disconnects after about 10 minutes | The server's TURN credential TTL is too short; increase `--turn-ttl` (43200 is recommended) |
| Recording files are missing | Make sure `RBLEACH_TERM_RECORD=0` is not set; check `%APPDATA%\rebleach\recordings` |

## 14. Command cheat sheet

```powershell
# One-step controller setup (register public key + generate ssh config)
rebleach-client --server <url> setup --device <controller-id> --user admin --pass <password>

# Remote execution
rebleach-client exec <device> -- "<command>"
rebleach-client exec <device> --json --timeout 60 -- "<command>"

# Port forwarding (loopback/private IP, or ssh)
rebleach-client tunnel <device> --local 13306:127.0.0.1:3306
rebleach-client tunnel <device> --local 2222:ssh

# SSH access
rebleach-client keygen --device <device> [--add]
rebleach-client ssh-config --controller <controller-id> [--backend builtin|sshd] [--user <u>] [--print]

# Ansible
$env:RBLEACH_PASS = "<password>"
rebleach-client inventory --user admin --only-online [--print]

# Recording replay
rebleach-client term-replay <path>.cast

# Protocol bridge (normally invoked by ssh)
rebleach-proxy --server <url> --id <controller-id> --device <device> --stdio rblssh
```
